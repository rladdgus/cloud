# 작업: 주간 점검 (매주 월요일 10:00)

먼저 이 폴더의 `cowork/00-공통-규칙.md`를 읽고 그 규칙을 지켜.

## 목표
지난 7일의 성과를 숫자로 정리하고, 다음 주에 **딱 한두 가지만** 바꿔서 실험해.

## 1단계: 자료 모으기
1. `data/state.json`의 `videos`에서 최근 7일(`created` 기준) 영상을 모아. 각 영상의 `title`, `category`, `views`, `likes`, `comments`, `seconds`, `status`를 표로 만들어.
   - `status`가 `rejected`인 영상은 따로 모으고, 폴더의 `rejected.txt` 사유도 함께 적어.
2. `data/ytauto.log`에서 최근 7일 동안 `ERROR`나 `실패`가 들어간 줄을 찾아 종류별로 세어.
3. `cowork/기록/` 폴더에서 최근 7일 기록을 읽고 "사람이 확인할 것"을 모아.
4. Chrome에서 YouTube Studio → **분석**을 열고 기간을 **지난 7일**로 바꿔서 아래를 적어.
   - 조회수, 시청 시간, 구독자 증감
   - **콘텐츠** 탭의 쇼츠별 "스와이프하지 않고 시청함" 비율 (보이면)
   - **시청자층** 탭의 "시청자가 YouTube를 이용하는 시간대"
5. 쿠팡 파트너스 → **리포트**에서 지난 7일 **클릭 수, 주문 수, 수익**을 적어. 로그인이 필요하면 이 부분은 건너뛰어.

## 2단계: 분석
1. 조회수 **상위 3개**와 **하위 3개** 영상을 비교해. 대본은 `output/폴더/script.json`에 있어 (폴더가 지워졌으면 제목만으로 비교).
   - 카테고리가 같은가?
   - 훅 문장(첫 장면 내레이션)이 질문형인가, 공감형인가, 놀람형인가?
   - 영상 길이는?
   - 훅 제목은 얼마나 구체적인가?
2. 잘된 영상의 공통점을 **한 문장**으로 정리해.
3. 불합격이 많았다면 가장 많은 사유를 찾아.

## 3단계: 설정 조정 (최대 2개)
`config.yaml`에서 **아래 항목만**, 한 번에 **최대 2개**까지 고칠 수 있어. 고친 줄 위에 `# YYYY-MM-DD 주간점검: 이유` 주석을 달아.

| 항목 | 바꿀 수 있는 방법 |
|---|---|
| `shopping.coupang_categories` | 성과가 좋은 카테고리를 앞으로, 3주 연속 성과가 나쁜 카테고리는 빼기 (최소 3개는 남겨) |
| `schedule.upload_times` | 시청자가 많은 시간대 1시간 전으로 옮기기 (하루 1~3개 유지) |
| `studio.motion.max_clips` | 0~3 사이. 움직이는 클립이 있는 영상이 확실히 잘되면 늘리고, 차이가 없으면 줄여서 비용 절약 |
| `quality.min_score` | 7~9 사이. 불합격이 너무 많으면 낮추고, 품질 문제가 많으면 높이기 |

위 표에 없는 항목(API 설정, 광고 문구, 업로드 방식 등)은 **고치지 말고** 보고서에 제안만 적어.

## 4단계: 보고서
`reports/YYYY-MM-DD-주간보고.md`로 저장해 (`reports` 폴더가 없으면 만들어).

```
# 주간 보고 (MM/DD ~ MM/DD)

## ⚠️ 먼저 볼 것
(반복 오류, 로그인 필요, 불합격 급증 등. 없으면 "없음")

## 숫자
| 항목 | 이번 주 | 지난주 |
| 업로드 수 | | |
| 불합격 수 | | |
| 총 조회수 | | |
| 구독자 증감 | | |
| 쿠팡 클릭 / 주문 / 수익 | | |

## 잘된 영상 3 / 안 된 영상 3
(제목, 조회수, 한 줄 이유)

## 이번 주 배운 점
(한두 문장)

## 바꾼 설정
(무엇을, 왜. 없으면 "없음")

## 다음 주 실험
(딱 하나. 예: "훅을 질문형으로만 써 보기")

## 사람에게 제안
(설정 표 밖의 변경 제안, 새 카테고리 아이디어 등)
```

지난주 보고서가 있으면 "지난주" 칸을 채워 비교해.
